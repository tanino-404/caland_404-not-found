### 人間の指示

スマホでも使えるようにするにはどうしたらいい？

### AI の応答

> 今のアプリは、スマホのブラウザで開く土台（`viewport`）はあります。足りないのは、縦長の画面に合わせた配置・カメラ・タッチ操作です。ライブラリは足さなくてよいです。
>
> 同じ Wi-Fi のスマホから開発中の画面を見るには、`src` で次を実行します。
>
> ```bash
> cd src && npm run dev -- --host
> ```
>
> ターミナルに出る `http://192.168.x.x:5173` をスマホのブラウザで開きます。
>
> 直す順番は次の 4 つです。
>
> 1. **画面の重なり**（`src/src/styles/global.css`、`YearIslands.css`）
>    右上のナビは `max-width: calc(100vw - 420px)` なので、幅 420px 未満では幅が潰れ、左上の巨大な月数字と重なります。720px 以下では凡例を隠す処理は既にあります。スマホでは月数字をさらに小さくし、ナビを月数字の下か画面下にまとめます。日ビューの予定パネルは右上に最大 360px で乗るため、縦画面では 3D の町がほとんど見えません。下から出すシートにして、町が上に残るようにします。年ビューは 840px 以下でも 2 列のままなので、狭い幅では 1 列にします。高さは `100vh` ではなく `100dvh` と、ノッチ分の `safe-area` を使います。
>
> 2. **縦画面のカメラ**（`src/src/lib/camera.ts`、`MonthScene.tsx`）
>    月俯瞰は fov 40 で、横長の机上画面向けの距離です。three.js の fov は縦方向なので、縦長だと横の見える範囲が狭く、7 列の島が左右で切れます。画面の縦横比が 1 未満のときはカメラを引く（距離を足す）だけで、月全体が入ります。
>
> 3. **タッチ**（`DayTower.tsx`、キャンバスの CSS）
>    `OrbitControls` は 1 本指で回転、2 本指でズームが既にできます。ホバーがないので、今の「当てると日付が出る」はスマホでは出ません。日をタップしたらそのまま日ビューに入り、戻るボタンで月に戻る、で足ります。指を滑らせて回している最中に日が開かないよう、動いたポインタはクリックにしない判定を足します。キャンバスに `touch-action: none` を置き、ブラウザのピンチ拡大と取り合いにしないようにします。ボタンは指で押せる高さ（おおよそ 44px）にします。
>
> 4. **描画の軽さ**（`MonthScene.tsx` の `Canvas`）
>    `dpr` が最大 2、全面に `backdrop-filter` のぼかしがあります。スマホでは `dpr` を 1.5 までに抑え、狭い画面では上下のぼかしを外します。
>
> 触るファイルは `global.css`（共有）と `camera.ts` / `MonthScene.tsx` / `DayTower.tsx` です。この方針で実装に入ってよければ、その 4 点を順に直します。

### AI の応答

> 最初に作るのは、ログインでも予定の取り込みでもなく、**1枚の地図の保存**です。
>
> 今の共有は `localStorage` の1つの JSON（`src/src/lib/storage.ts` の `SharedCalendarState`）です。中身は `members`（名前の一覧）と `events`（日付・タイトル・種類・所有者）だけです。同じブラウザの中でしか揃いません。スマホとパソコンで同じ島を見るには、この JSON をサーバーに置く必要があります。
>
> 作る順は次です。
>
> 1. **地図1枚を読み書きする API。** `GET` でその JSON を取り、`PUT` で丸ごと戻す。認証はまだ付けない。`currentUser`（今誰として見ているか）はブラウザごとに違うので、サーバーには置かず、今どおり画面側に残す。
> 2. **`useSharedCalendar` の保存先を、その API に差し替える。** 画面のボタン（建てる・参加する・抜ける）はそのまま。変えるのは `commit` が `localStorage` ではなくサーバーを書くところだけ。
> 3. **もう一方の画面へ反映する。** 数秒ごとの再取得で足ります。WebSocket は、二人で同時に触って取りこぼしが出てからでよい。
>
> パスワード付きログインと、カレンダーのインポートは後です。名前だけの参加はもう動いていて、デモで足りないのは「別の端末から同じ地図が見えること」です。
>
> サーバーの形は、データベースを分けず、この JSON を1件保存するだけで足ります。静的ホスティング（GitHub Pages）とは別の場所に置くことになります。

### AI の応答

> 上げる先は Cloudflare です。ここに、島の画面のファイルと、予定一覧を覚えているプログラムを一緒に送ります。送ったあとのアドレスは、このパソコンの電源と関係なく開けます。GitHub の公開ページは作りません。
>
> まだ、送るプログラムはこのパソコンにありません。先にここで動かし、そのあと送ります。
>
> 1. このパソコンで、予定一覧を読み出せて、入れ替えて保存できるプログラムを作ります。見本の予定（たろう、はなこ、2026年）を最初の中身にします。「今この画面では誰として見ているか」は、この一覧に書きません。
> 2. 島の「建てる」「参加する」「抜ける」が、ブラウザの中ではなく、そのプログラムの一覧を書き換えるようにします。このパソコンでブラウザを二つ開き、片方で予定を足し、もう片方を開き直して同じ予定が見えれば、ここまでできています。
> 3. Cloudflare の無料アカウントを作ります。登録は https://dash.cloudflare.com/sign-up です。
> 4. このリポジトリの一番上に、送るための設定ファイルを置きます。このファイルはみんなで共有するので、置く前にチームに声をかけます。画面では、予定を覚えておく箱は KV という名前で出ます。箱は一覧を一つだけ覚えます。
> 5. ターミナルで Cloudflare にログインし、箱を一つ作ります。
>
> ```bash
> npx wrangler login
> npx wrangler kv namespace create CALENDAR
> ```
>
> ログインはブラウザが開くので、そこで許可します。2行目の結果に出る id を、手順4の設定ファイルに書きます。`npx` は送る道具をその場で取るので、共有の `package.json` は変えません。
> 6. 島の画面を組み立てて、Cloudflare に送ります。
>
> ```bash
> cd src && npm run build
> cd .. && npx wrangler deploy
> ```
>
> 終わると `https://（名前）.workers.dev` というアドレスが出ます。
> 7. そのアドレスをスマホで開きます。島が見え、予定を1件足します。このパソコンの電源を切り、別のスマホで同じアドレスを開きます。足した予定の分だけ島が高ければ、完了です。
>
> このアドレスを知っている人は、パスワードなしで一覧を書き換えられます。パスワードは、この手順のあとで足します。
