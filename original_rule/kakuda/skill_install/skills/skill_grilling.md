---
name: grilling
description: 計画・判断・アイデアを質問で徹底的に詰める。思考をストレステストしたいとき、「grill」「詰めて」などの合図で使う。Use when grilling a plan, decision, or idea.
---

共有理解に達するまで、人間を徹底的にインタビューする。これを **設計ツリー** として扱う。すべての判断は、そこからぶら下がる判断へ枝分かれする。

ツリーは **ラウンド** で進める。**フロンティア** は、前提がすでに決まった判断、つまり未回答を推測せず **今** 聞ける質問である。1ラウンドでフロンティア全部を聞く。各問に番号を振り、推奨回答を付ける。次のラウンドの前に、人間の回答を待つ。

ラウンドの書式：

```
❓ **Q1** - **<質問の見出し>**: <本文。複数段落・選択肢可>

➡️ <あなたの推奨回答>

---

❓ **Q2** - **<質問の見出し>**: <本文。複数段落・選択肢可>

➡️ <あなたの推奨回答>
```

人間が答えるたびにツリーは形を変える。決まった判断がフロンティアを外へ押し、それに依存していた質問が解禁される。フロンティアを再計算して次ラウンドを聞く。同じラウンド内でまだ開いている別問に答が依存する質問は、**後のラウンド** に回す。

**事実** を探すのはあなたの仕事であり、人間の仕事ではない。フロンティアの問が環境（ファイルシステム、ツール等）の事実を必要とするときは、サブエージェントに調べさせる。自分で調べられることを人間に聞かない。ブロックしない。進行中の調査は未決の前提なので、その下流の問だけが報告を待ち、残りのフロンティアは今聞く。**判断** は人間のものなので、1つずつ出して待つ。

フロンティアが空になったら終了。設計ツリーの全枝を訪れ、黙った前提が残っていない。人間が「共有理解に達した」と確認するまで、実装には着手しない。

本プロジェクトでは、質問は 5 分・10 問以内で打ち切る。決まったことは人間が `docs/human_idea/concept.md` に反映する。
