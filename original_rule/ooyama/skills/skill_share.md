# share — このプロジェクトを安全な場所に保存する

ユーザーは git、リポジトリ、リモートが何かを知らないかもしれません。すべての
メッセージを平易な言葉で書いてください: プロジェクトには **公開されない
オンラインコピー** が作られ、後から復元、同期、共有できます。「リモートに push」
ではなく「保存」「バックアップ」と言うこと。（git に習熟したユーザーにも同じ
フローをこの言い回しなしで提供します — これは `new-repo` スキルのフローを
初心者向けの語彙にしたものです。）

## 1. 話す前に確認する

```bash
git rev-parse --is-inside-work-tree 2>/dev/null
git remote -v
```

- **リモートが既に存在する** → プロジェクトは既にそこへバックアップされて
  います。最新の変更をそこへ保存する（commit + push）ことを提案して止まる。
  2 つ目のコピーを作ったり、既存のリモートに触れたりしないこと。
- git がまったくない → 問題なし。ステップ 3 で静かにセットアップする。

## 2. 一行での説明

これから何をするかを、一行でユーザーに伝えます:

> "I'll put this project in a repo — a saved, versioned copy you can restore
> or share later. It won't be public."

このスキルは、プロジェクトを Cursor ホストのリポジトリに保存します。ユーザーが
明示的に別のホストを求めた場合は、このスキルを使わずその依頼に従ってください。

デフォルトでは、プロジェクトフォルダにちなんだ名前（小文字、ダッシュ区切り）の
リポジトリにします。

## 3. セットアップして保存する

何かをステージする前に、コミット対象になるものを一覧し
（`git status --porcelain` または `git ls-files -o --exclude-standard`）、
`.gitignore` が依存ディレクトリと秘密情報（`.env*`、鍵や認証情報のファイル）を
カバーしていることを確認します。秘密情報に見えるものがステージされそうな場合は、
含める前に確認する — 盲目的に stage して push しないこと。

```bash
git init -b main   # only if not already a repo
git add -A && git commit -m "Initial commit"   # only if nothing committed
```

`origin` が見つからない、未認証、または古い場合は、まず `origin` スキル
（`~/.cursor/skills-cursor/origin/SKILL.md` に同期済み）を呼び出します — ユーザーには
「まず Cursor のリポジトリツールをセットアップします。各ステップが表示されます」と
伝えます（サインインはブラウザが開きます。そこはユーザーの担当です）。その後:

```bash
origin repo create <name>
git remote add origin <clone URL printed by create>
git push -u origin main
```

アカウントに名前空間がない、またはアクセス権がないために `origin repo create` が
失敗しても、何も失われていません — `origin` スキルの復旧テーブルに従ってください
（平易な言葉で言うと「チームの管理者がこの機能を有効にする必要があります」）。

## 4. ユーザーの語彙で締めくくる

保存先を報告します — `https://cursor.com/codebase/<org>/<name>`（create の出力
から）— そして公開されないことも伝えます。アカウントがチームに所属している場合は、
チームのスペース内のリポジトリはチームメイトにも見えることを率直に伝えます。
アクセスはリポジトリページから管理します。最後に、変更を加えた後はいつでも
「また保存して」と頼めることを伝えて締めくくります。

## 目的が誰かに見せることだった場合

保存されたコピーが一般に公開されることは決してありません。誰が既に見られるかは
アカウントによります: 個人アカウントならユーザー本人だけ、チームならチームの
スペース内のチームメイトも見られます。それ以外の人に見せるには、リポジトリ
ページ（上記の URL）でアクセス権を管理するよう案内してください — このスキルでは
変更できないので、リンクだけで他の人が見られるとは決して約束しないこと。

## 厳守事項

- プロジェクトに既にリモートがある場合、リポジトリを作成しない。
- リポジトリを削除しない。既存のリモートを変更しない。
- 一般公開やリンク共有を約束しない。アクセスはリポジトリページから管理する。
- ユーザー向けの文章で git の専門用語を使わない。
