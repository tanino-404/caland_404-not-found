# Split to PRs（PR への分割）

ひとまとまりの作業を、いくつかの小さな PR に変換します。

## 厳守ルール

- ユーザーが分割プランを承認するまで、ブランチ作成・コミット・プッシュ・PR 作成を行わないこと。
- ユーザーの作業を絶対に破棄しないこと。明示的な承認なしに破壊的な git コマンド（`reset --hard`、`clean -fdx`、ブランチ削除、force push、履歴の書き換え）を実行しないこと。
- 作業を動かす前に、必ず復元可能なスナップショットを保存すること。この作業は `main` 上の未整理（dirty）な作業から始まることが多いため、すでに安全なブランチがあると想定しないこと。
- ステージするのは名前を指定したファイルまたはハンクのみ。`git add .` / `git add -A` は禁止。

## 1. 状態を確認する

コミット済み・未コミットの変更を含めて、現在の作業をリポジトリのデフォルトブランチと比較します。実際に見えた作業のかたまり（スライス）を要約し、チャット履歴を使って意図を復元します。

スライスを提案する前に、変更対象のパスに関するオーナーシップの手がかり（`CODEOWNERS`、ネストされたオーナーシップファイル、またはリポジトリでそれに相当するもの）を探し、それを使って自然なレビュアーの境界を特定します。

## 2. 分割を提案する

詳細度は状況に応じて判断します。通常は PR タイトルだけで十分です。タイトルだけでは不明瞭な場合にのみ、1 行のスコープ補足を追加します。スライスが複数ある場合は Mermaid 図を表示します。

無関係な差分を最小限に抑えた、レビュアーに沿った PR になるよう最適化します。独立したオーナーや関心事は分割し、密結合な変更はまとめて保ち、スタック（積み重ね）が必要な場合は基盤となる変更を利用側より先に並べます。

デフォルトでは、デフォルトブランチから派生する独立した PR とします。PR をスタックするのは、依存関係が実際に存在する場合に限ります。

開始前に承認を求めます。

## 3. 分割を実行する

- 未コミットの作業がある場合は、ワーキングツリーを変更せずに復元可能なスナップショットを保存します:

  ```bash
  SHA=$(git stash create "pre-split")
  if [ -n "$SHA" ]; then
    git update-ref "refs/backup/pre-split-$(date +%s)" "$SHA"
  fi
  ```

- 承認された各スライスについて、適切なベースからブランチを作成し、計画したファイルまたはハンクのみをステージしてコミットし、プッシュして PR を作成します。

## 4. 報告する

簡潔に: PR のタイトルと URL、および開始ブランチやワーキングツリーに残っているものを報告します。ユーザーが依頼しない限り、バックアップ ref や元のブランチを削除しないこと。
