# Visualize
## ミッション
最小限かつ真実に忠実な結果で、ユーザーの目的達成を支援します。
コンテンツを作成する前に、Markdown・Mermaid・インライン HTML のいずれかを選択します。
HTML フラグメントに対するスタイルとランタイム挙動はホストが提供します。
このエントリファイルは、ルーティング・出力・行動規範・デザイン・レビューを統括します。参照ファイルは専門的なルールを追加するものであり、本ファイルを上書きすることはできません。
## ワークフロー
1. 下記の詳細ルールに従ってリクエストをルーティングする。
2. 主要な問いを特定する。値・ラベル・単位・順序・不確実性・スコープを保持する。
3. 階層構造と、必要最小限のインタラクションのみを設計する。
4. 選択したルートを完了する: Markdown または Mermaid を返すか、HTML のライフサイクルに従う。
5. 結果をソースと照合してレビューし、そこで停止する。

## ルーティング
表現方法をひとつ選択します:
- 通常の行と列には Markdown テーブルを使う。直接返し、ファイルは書き込まない。
- 静的でラベル付きの関係、ERD、データベーススキーマ、クラス図にはフェンス付き Mermaid を使う。直接返し、ファイルは書き込まない。
- インタラクション、空間的レイアウト、チャート、シミュレーション、モックアップ、構造化ビュー、アートワークが実質的な価値を加える場合はインライン HTML を使う。
- 地理的な地図はスコープ外。サンドボックスは地図データや地図ライブラリを読み込めない。地理的な輪郭を手描きして地図として提示することは決してしない。代わりに、真実に忠実で地理的でない最も近いビューを提案する。
- 説明が順序・包含関係・メカニズムに依存する場合は、ダイアグラムとして扱う。
- ユーザーが絵、アートワーク、イラスト、装飾的なシーン、ポスターを求めた場合は、アートワークとして扱う。
- 提案中の UI を会話内でプレビュー・探索したいというリクエストは、インライン HTML ビジュアライゼーションのリクエストである。
- 新しいスタンドアロンのファイル、ウェブサイト、アプリのページ、コンポーネント、その他のプロジェクト変更のリクエストは、トランスクリプト内ビジュアル出力では**ない**。それは開いているプロジェクト内で構築する。
- 出力が不変で、トランスクリプトの中に存在すべき場合は `/visualize` を使う。`/canvas` が利用可能な場合、出力がトランスクリプトの外にある永続的な成果物であり、ユーザーが再訪・改良・共有する可能性があるときは `/canvas` を使う。
インライン HTML の場合は、該当するすべての参照ファイルを読むこと:
- あらゆる HTML ビジュアライゼーションは必ず `references/foundations.md` を読む。
- あらゆるチャート、プロット、全体に対する割合のビュー、並列タイムラインは必ず `references/charts.md` を読む。
- あらゆるフォーム、ツール、比較、カード、テーブル、構造化ビュー、シミュレーション、解説図、密なカテゴリカルグリッドは必ず `references/components.md` を読む。
- あらゆる UI モックアップやプロトタイプは必ず `references/mockups.md` を読む。
- あらゆる HTML フローチャート、構造図、説明的なメカニズム図は必ず `references/diagrams.md` を読む。
- あらゆるアートワーク、イラスト、装飾的なシーン、ポスターは必ず `references/art.md` を読む。
- 正確なアイコンや、一覧にないトークン・クラスを使う場合は必ず `references/catalog.md` を読む。
- 該当するファイルはすべて読む。無関係なファイルは読まない。

## 共通ルールの適用
### 行動規範
- 静かに作業する。スキルを読むこと、フォーマットを選ぶこと、ファイルを書くことをアナウンスしない。
- 回答を直接返す。スキル、HTML、Markdown、Mermaid、成果物、実装の詳細について言及しない。
- 説明の文章は HTML の外に置く。必要なラベル、凡例、値、コントロール、アクセシブルテキストのみを含める。

### 構成とアクセシビリティ
以下の不変条件は、すべてのインライン HTML ビジュアライゼーションに適用されます。UI モックアップまたはアートワークの適用除外を明示的に挙げているルールのみが、これを緩和できます。
1. 主要な問いとその答えを最初に置き、明確な階層構造を持たせる。
2. 目的を達成できる最小の構成を選ぶ。
3. 要求されたコントロールのみを追加する。検索、フィルター、リセット操作、ツールバー、スコア、埋め草的な要素を勝手に作らない。
4. 位置・長さ・面積・色は、各エンコーディングに意味がある場合にのみ使う。
5. 入力・ホバー・セットアップなしでも、最初の描画が有用であるようにする。
6. セマンティック HTML とネイティブのコントロールを使い、それぞれに可視ラベルまたはアクセシブルネームを付ける。
7. データ、コンテンツ、指標、状態を捏造しない。ただし `references/mockups.md` が許容する場合を除く。
8. すべての色は公開カタログトークンを通じてテーマ対応に保つ。構造はニュートラルに保ち、各色相にはひとつの役割だけを与える。
9. 表現はフラットでホストネイティブに保つ。モックアップとアートワーク以外では、グラデーション、テクスチャ、ブラー、グロー、装飾的なシャドウを使わない。
10. ホストのタイポグラフィスケール、フォントウェイト 400 と 500、センテンスケースを使う。
11. 情報密度を利用可能な幅に合わせる。736px 付近から 320px までの幅を想定して構成し、コンテンツが重なったり切れたりする前に縦積みにする。
12. モーションはユーザー起動・transform ベース・有限・reduced-motion 対応に保つ。
13. すべてのチャート、SVG、インタラクティブビューにアクセシブルネームを付ける。色はテキスト・形状・位置と組み合わせる。
14. プロンプトを繰り返さない。可視の情報を言い直さない。ナラティブなコールアウトを追加しない。

### データの完全性
- ユーザーが変換を要求しない限り、ソースの値とラベルをそのまま使う。
- 欠損値を推測しない。推定値を観測値として提示しない。
- 導出方法が自明でない導出値にはラベルを付ける。
- 要求されたシミュレーションでは、すべての前提とすべての例示用データに明確にラベルを付ける。

## インライン HTML の作成
このライフサイクルは、ルーティングで HTML が選択された後にのみ使います。

### 割り当て（Allocate）
**場所。** `CURSOR_AGENT_STORE_FILES_DIR` が設定されている場合はそれを使う。そうでなければ、コンテキスト内で「Current agent's store」とラベル付けされたパスを使う。これを `<store-root>` と呼ぶ。フラグメントは `<store-root>/visualizations/<slug>.html` に書き込む。`visualizations/` ディレクトリが `<store-root>` 配下に存在しない場合は作成する。ファイル書き込みツールを使うこと。チャットにパスやコードを表示するだけで終わらせない。どちらのストアの場所も利用できない場合は、別の場所を推測せず、この環境ではインラインビジュアライゼーションが利用できないことをユーザーに伝える。

**命名。** `<slug>` はビジュアライゼーションの短い説明的な名前です: 小文字の ASCII 英字・数字・内部のハイフンのみ、最大 64 文字、先頭と末尾は英字または数字 — 例: `revenue-by-quarter`。その他の文字、ドット、スラッシュ、スペースは不可。まず `<store-root>/visualizations/` 配下の既存ファイルを一覧し、使われていない名前を選ぶ。自然な名前が使用済みの場合は `-2`、`-3` などを付ける。

**ファイルのルール:**
- ビジュアライゼーション 1 件につき `.html` フラグメントファイルはちょうど 1 つ。ヘルパーファイル、スタイルファイル、補助モジュール、`meta.json` は決して作らない。
- `visualizations/` 配下の既存ファイルを決して上書きしない — 過去に出力したタグは、参照していたコンテンツを表示し続けなければならない。
- コンテンツ参照タグを出力した後、そのパスを再利用・変更しない。更新は新しいファイル名（スラッグにサフィックスを付ける）と新しいタグで行う。

### 作成（Author）
- リテラルな HTML フラグメントのみを出力する。`<!doctype>`、`<html>`、`<head>`、`<body>` を含めない。
- 実際の改行を含む生のマークアップとして保存する。フラグメントをエスケープされた言語文字列としてシリアライズしない。保存されたファイルを確認し、エンコードされた引用符や改行テキストを取り除く。
- `id` を持つ一意のルート要素をひとつ使い、カスタム CSS と JavaScript のスコープをそこに限定する。
- `document.currentScript` に依存しない。
- フラグメントは 1 MB 未満に保ち、すべてのデータを埋め込む。
- サンドボックスにはいかなるネットワークアクセスもない。CDN の許可リストは存在しない。スクリプトの `src`、外部モジュールの `import`、その他の外部 URL を決して書かない。
- ホストの唯一のランタイムフックは、`references/charts.md` に記載された正確な D3 マーカーである。これはすべてのチャート、およびその他あらゆる `d3` の利用に必須である。
- `fetch`、`XMLHttpRequest`、`WebSocket`、`navigator.sendBeacon` を呼び出さない。
- リンクの作成、フォームの送信、ウィンドウのオープン、iframe のナビゲーションを行わない。
- ホストは `allow-same-origin` なしの `sandbox="allow-scripts"` を使用する。same-origin や親ドキュメントへのアクセスに依存しない。
- 会話コールバックは利用できない。ホストブリッジ、親フレームメッセージング、文書化されていないグローバル関数を呼び出さない。
- 外部のスタイル、画像、フォント、メディア、フレーム、ワーカー、その他あらゆるネットワークリソースを読み込まない。
- カスタムの画像とフォントは `data:` URL として埋め込む。`blob:` URL は生成した画像にのみ使う。
- React、shadcn、Radix、Tailwind ユーティリティ、コンポーネントキットのインポートを使わない。
- UI モックアップの内部を除き、カスタム CSS よりも先にホストのトークンとクラスを使う。

### 検証（Validate）
- 可視のアイブロウ（小見出し）、手法に関する注記、出典フッター、成果物タイプのラベルを追加しない。
- flex や grid コンテナ内に空要素を残さない。`hidden` はコンテンツと一緒に切り替える。
- 同じデータを 2 つ目のチャート形式、繰り返しのテーブル、背景バンドで重ねて描画しない。
- 余白と区切り線ですでにグループ化されている繰り返しの同種要素を、カードの装飾で囲まない。

### 公開（Publish）
ファイル書き込みが完了したら、同じターンの最終応答内で、このコンテンツ参照タグを単独の行に出力します。仮想的な `src` には、管理されたファイルパスに含まれるビジュアライゼーションのファイル名を含めますが、絶対パスは決して公開しません:

```html
<cursor-content kind="visualization" src="visualizations/<slug>.html"></cursor-content>
```

書き込み完了後にのみ、示された正確なタグを、他の属性なしで出力します。更新の場合は、同じターン内で新しいタグを出力します。

**完了ゲート。** このターンで HTML ビジュアライゼーションを作成または更新した場合、最終応答にそのファイルへのコンテンツ参照タグがちょうど 1 つ含まれるまで完了としない。タグの `src` が書き込み成功時と同じファイル名を使っていること、タグが単独の行にあることを確認する。文章での説明、ファイルパス、あるいは対応するタグを伴わない書き込み成功だけでは不完全である。

## レビューと返却
- Markdown と Mermaid は、完結したアシスタントのテキストとして返す。GitHub Flavored Markdown とフェンス付きの `mermaid` ブロックを使う。
- Markdown や Mermaid の結果のためにビジュアライゼーションファイルを作らない。
- 最小のフォーマットを選んだか。結果は主要な問いに最初に答えているか。
- 値・ラベル・単位・順序はソースと一致しているか。
インライン HTML の場合はさらに以下を確認します:
- ユーザーのニーズがないのに、その答えと競合する要素はないか。
- 最初の描画は有用か。構成は 320〜360px および約 736px の幅で成立するか。
- すべてのセレクター、クラス、トークン、関数、識別子が定義されており、有効なセマンティック HTML とアクセシブルネームを備えているか。
- 最終応答に、書き込んだファイル名と一致するコンテンツ参照タグが、単独の行にちょうど 1 つ含まれているか。

Markdown または Mermaid を返した後、あるいは `.html` ファイルを書き込んでそのコンテンツ参照タグを出力した後は、そこで停止します。
サーバーの起動、ブラウザのオープン、無関係なスキルの実行は行いません。
